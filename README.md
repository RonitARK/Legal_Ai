# LegalAI India

LegalAI India is an AI-powered labour-code compliance engine for reviewing HR policy documents. Upload a policy PDF to extract its text, analyze it against configured Indian labour-code rules, identify compliance gaps, and download a generated PDF report.

> **Disclaimer:** This project is an informational compliance-assistance tool and does not provide legal advice. Have qualified legal counsel review important decisions and policy changes.

## Features

- Upload HR policy documents as PDF files.
- Extract text from uploaded PDFs on the backend.
- Analyze policies against labour-code compliance rules using an AI service.
- Return an overall compliance score, summary, identified gaps, severity levels, and compliant areas.
- Download the analysis as a PDF compliance report.
- Expose health and audit endpoints through a FastAPI backend.
- Provide a Next.js frontend with drag-and-drop upload and interactive findings.

## Requirements

- Python 3.10+

- npm

## Backend setup

From the repository root:

```bash
cd backend
python -m venv .venv
```

Activate the virtual environment:

```bash
# macOS/Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Install the backend dependencies. If a dependency file is added to the project, use it directly; otherwise install the packages required by the application, including FastAPI, Uvicorn, Pydantic Settings, PDF parsing, report generation, and the configured AI client.

Create `backend/.env` and configure the AI API key expected by `backend/app/core/config.py`:

```env
GEMINI_API_KEY=your_api_key_here
```

Start the API from the `backend` directory:

```bash
uvicorn app.main:app --reload --port 8000
```

The API will be available at `http://localhost:8000`.

## Frontend setup

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:3000` in your browser.

The frontend currently sends audit requests to a configured backend URL in `frontend/app/page.tsx`. For local development, update that URL to point to `http://localhost:8000` or expose the backend at the configured development URL.

## API endpoints

The backend mounts its routes under `/api/v1`:

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/api/v1/health` | Check whether the compliance engine is running. |
| `POST` | `/api/v1/audit` | Upload a PDF and run a compliance audit. Use multipart form field `file`. |
| `POST` | `/api/v1/audit/report-from-result` | Generate a downloadable PDF report from an analysis result. |

Example audit request:

```bash
curl -X POST http://localhost:8000/api/v1/audit \
  -F "file=@backend/test_hr_policy.pdf"
```

Interactive API documentation is available at `http://localhost:8000/docs` when the backend is running.

## Frontend scripts

Run these commands from `frontend/`:

```bash
npm run dev      # Start the development server
npm run build    # Create a production build
npm start        # Serve the production build
npm run lint     # Run ESLint
```

## Development notes

- Only PDF uploads are accepted by the audit endpoint.
- Uploaded PDFs must contain enough readable text for analysis.
- Do not commit `.env` files or API keys.
- The compliance result is generated by an AI-assisted workflow and should be verified before being used for policy or legal decisions.
